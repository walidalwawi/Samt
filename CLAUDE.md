# Walid Al Wawi · CLAUDE.md

## What this is
Static site for walidalwawi.com on Cloudflare Workers (static assets, free plan). Pushing to `main` deploys.
Source of truth is `content/site.json`; the back office at /admin renders and publishes it.

## Back office (site/admin.html + site/admin/grid.*)
Walid's Site Grid editor — ONE back office for walidalwawi.com and samt.co. Identical files in both repos (site/admin.html differs only in BD_HOST); change one, copy to the other. BD_SITES in admin.html lists the sites; the switcher stores the choice in localStorage bd-site-current. One GitHub key (bd-gh-key) covers both repos.
- Blocks: text, image, gallery, library, link, notes, list, video, html, rule, quote, fold-out list (toggle), product; site blocks menu (list or button + overlay, with brand text beside it), page title, page arrows (arrows or "Next, title" words; pages or blog scope); blog blocks posts (cards grid/columns/list, featured, card look) and post info (back link, words ~ minutes).
- Blogs: a page with `blog: true`; posts are pages with `parent: <blog id>`, plus `date`, `excerpt`, `featured`. Posts are skipped by the menu and by site-scope page arrows. Cards use the post's h1 || title, first image, and word count.
- Prefer a real block over an html block; html blocks are for genuine one-offs.
- Inspect: picks any element in the canvas; design bar writes rules into site.css or page.css via cssSplit/ruleSet; on Phone into the single @media (max-width: 760px) block, which Publish merges into bd.css's one mobile block.
- Code drawer is CodeMirror 5 (cdnjs). Files tab edits any non-generated repo file and uploads to site/files/ or site/images/; both ride in the publish commit.
- Loads content/site.json from GitHub with Walid's fine-grained token (kept in his browser only).
- Draft autosaves to localStorage (bd-draft-<repo>) until Publish.
- Publish = one commit: content/site.json, content/manifest.json, every page .html, site/404.html, site/assets/bd.css (stamped "PUBLISHED <id>"), site/assets/bd.js, new images (uploaded earlier as git blobs). Pages in the old manifest but not the new one are deleted. Then polls /assets/bd.css for the stamp.
- Image props: assetId "live" (in site/images), "sha:<blob>" (uploaded, not yet published), "remote" (still hot-linked from an old URL; Publish tries to copy it in).

## Layers (site.layers.on + site.sheets) — the paper-sheet site (used by samt.co)
Any page can lie on a translucent sheet; site.sheets is the stack, top → bottom (list order = z order). Pages not on a sheet lie underneath (content layer), one shown at a time.
- A sheet (SHEET_DEFAULTS): pages (ordered; several = it slides between them, axis y/x), rest (open | still | peek | hidden; still = never moves, lies where it is like a card in a stack), restPage (with rest=peek: the page drawn on the edge, always there — sheetStrip(k); the other pages are the panes, sheetPanes(k)), edge/edgeM (where it parks, desktop/phone), peek/peekM px (how much of the rest page shows), sliver/sliverM px (what an open sheet leaves showing when a page underneath opens; from its own edge plus the strips of peeking sheets above on that edge, so it is visible beside them; out=hide ignores it), covers (all | some + coverPages), color/alpha/blur/shadow (none | line | hard; was `line`), nudge (px a peeking sheet slides out on hover, desktop with hover, not over a link), dur. Older fields strip / paneW / pad / padM migrate on load (strip → pages + restPage; paneW/pad → the pane pages' box maxW/pl/pr).
- Menu+About and Journal+Library are the same thing: a sheet with two pages. The menu is a page ("Menu") holding a Sheet menu block (sheetmenu: menu, marker, align, style, pad/padM, gap/gapM, mark); it is the Menu sheet's rest page.
- Where it's edited: Pages tab → "+ Sheet" (a sheet with one fresh page), sheets show as groups with their pages indented ("edge" tag = rest page). Tapping a sheet's title in Pages selects the sheet (S.sheetSel): the right panel becomes the sheet panel (sheetPanelHTML → sheetEditHTML, the ONLY place sheet settings live: pages + spread axis, Paper = fill (None / Solid / Gradient with a clear end) + see-through + blur + pattern (lined / squared / dotted / ruled; sheetPattern, sheetPaper) + edge, Margin & padding (k.box; margin px or %, padding px, phone M variants; sheetEx / sheetPadIns), movement (parks at, at rest, leave = peeks or hides (k.out), Leaves with = per-sheet transition k.lv → class is-lv-<t>, Appears slide / fade / cut → is-ap-*, speed), lies over). Tapping a page returns the right panel to that page; its "Lies on" has a Sheet settings button. The sheet panel also holds Stack position (Higher / Lower) and Dissolve; the Site tab only has the on/off switch and a count (no sheet settings anywhere else). Motion tab = how every sheet moves by default; a sheet overrides speed and leave in its own panel.
- A page lying on a sheet has an inset (page.box m*), not a margin: see Page inset below. Padding/card stay on the panel (pageBoxCSS with noMargin). A page with a max width on a sheet sits at the left; underneath it centres. For pages underneath, margins inset the panel and sheetBg fills behind.
- Blur lives only on sheets (backdrop-filter, sheetBlur = sqrt(own blur² + "comes into focus" blur²)); the content layer is never filtered, so what a smaller sheet doesn't cover stays sharp.
- A sheet with its own top margin rises first: wheel/touch scrolling uses up the margin (--k-up on the sheet, top = ins + --k-mt − --k-up, runtime in bdLayers), then the page scrolls inside it; at the top, scrolling up brings the margin back. Pages underneath scroll their margin away natively.
- Sheets only ever slide in a straight line: a sheet keeps the margins of the page it shows while it tucks/hides (onPage), and its box changes instantly (is-snapbox) whenever its state changes, so top/left/right/bottom never animate during a slide.
- Sheet behaviour is the drawn geometry (layWrite): the ★ page is the page the window sits on at rest (k.main; for a strip, k.restPage). If the ★ page is first/last and the sheet's margin on that side cuts into it (the other pages lie beyond the window), the ★ page is either a strip (rest=peek, edge = the window side the sheet occupies, peek = the visible px, that side's box margin stays blank) or a page (rest still/open with the cut stored as a box margin) — the "The ★ page is" choice under the drawing (lay-strip, k.layPg remembers an explicit "page"; a new cut below 50% defaults to strip). ▽ (data-lh=away) = where the sheet goes when a page underneath opens: dragged onto itself = rest still; dragged out = rest open + edge + out peek/hide + sliver (visible px minus the peeking strips on that edge). Hidden at rest is a seg in Exact numbers (lay-hide). Phone drags write only *M numbers; what a sheet is (strip/page/still/open) is decided on the desktop. sheetMove / sheetMoveState remain as a programmatic API (tests) but have no UI.
- Page inset replaces page margin on sheets: page.box m* on a page lying ON a sheet is an inset (insetCSS: margin on the panel inside the pane, the sheet's paper shows around; pane stays full). It no longer moves the sheet's edges (sheetMarginCSS removed). Underneath pages keep real margins. The rise-first scroll now follows the SHEET's own top margin (k.box.mt → --k-mt on the sheet, bdLayers --k-up). Canvas: .bd-site.is-layered::before paints the paper inside the sheet's own margins; the panel carries the inset.
- Sheet panel (settings pane, 420px for a sheet; sheetEditHTML) order: Layout (name · layout drawing · caption sentence (layCaption) · "The ★ page is" strip/page when cut · legend · spread axis · + page chooser) · Style (Background colour / effect / decoration) · Animation (On appear = k.arrive, On leave = k.lv, On hover = k.hover none | nudge | lift → is-hv-lift, --k-nudge; desktop hover only) · Exact numbers (folded: margins, padding, strip px / left-showing px, At rest As drawn | Hidden) · Lies over · Stack. There is no Behaviour section any more. A page on a sheet inherits the sheet's style; it can set its own card colour / see-through / blur, `page.pattern` (inherit | none | pattern, pagePaperK) and `page.hover` (lift). Sheets stack in panel order (z-index), and anything smaller than the window or see-through shows what lies under it.
- Paper is painted on the panes (and the edge strip), not on the sheet box: a gradient uses `local` attachment and is sized N× the pane so it runs over the whole scroll area and continues across the sheet's pages (sheetPaper(k, pct, j, N); axis y/x). Pattern layers sit on top of it.
- Phone: a page's own padding overrides the desktop peek inset (pageBoxCSS `passed` flag), so the Journal never keeps the menu's 300px on a phone.
- Layout drawing (sheetGeo → layoutDrawing; layApply → layWrite; the ONLY place anything is dragged): everything in window px (1280×800 / 390×780 by Desktop/Phone), the window at (0,0). sheetGeo(n, phone) lays the sheet flat: N pages along the axis, the ★ page's slot under the window, margins from k.box (a strip's cut from peek), other sheets as dashed purple ghosts at rest, the away ghost (dashed) where it goes when a page underneath opens. Colours: purple sheet (#7b5ea7), red pages (#d23b3b), blue window (#2e9bd6), orange halves; the grid is the WINDOW's 5% grid tiled over the sheet. Handles `[data-lh]`: sheet edges (along-axis sides = mStart/mEnd, across = box margins), page edges (page.box m* insets, 16 svg units inside the edge, data-off), ▼ win (drag along the axis onto a page = ★), ▽ away (free drag; dominant axis = edge; snaps to 5%). × (lay-rm) takes a page off; the + page tab past the sheet's end (lay-add) opens the chooser (sheet-page-add / lay-new); tapping a page (lay-page) selects it. layMigrateOrderIn (once, site.layOrderV1) moves a left/top strip to the END of its sheet's pages and a right/bottom strip to the START so the spread reads the right way round.
- Scrollbars (scrollCSS, /* SCROLLBARS */): thin black line everywhere (scrollbar-width/color + ::-webkit-scrollbar). With layers on the native bars of panes and the content layer are hidden and one draggable black line (#bd-ly-bar, runtime bar()) sits on the window's far right edge for whichever page is scrolling.
- Fills: a sheet's colour, a page's card colour and "behind the page" can be a solid or a two-colour linear gradient (string "linear-gradient(<n>deg, #a, #b)"; fillIn UI = Solid | Gradient via the `fill.<part>|<path>` pseudo-paths in applyPath; parseFill/fillCSS apply the sheet's see-through to both stops; the value "none" paints nothing and a gradient stop may be "transparent" (fill.ends pseudo-part); bgVal() maps none → transparent).
- A sheet that parks on an edge (rest=peek) is inset by the peeks of the peeking sheets above it (sheetBoxIns); every other sheet starts at the window's edge and lies UNDER them (translucent), and only its pages' content is padded by those peeks (pageBoxCSS ins + noMargin). Page margins are measured from the window edge. Pages underneath are padded by all peeking sheets.
- bdSheetPlan(K, focus, prev) — exported as-is, used by Publish (initial classes) and the runtime: the page's own sheet opens on it; sheets above go back to rest (open-at-rest ones tuck); sheets below keep what they were doing; a page underneath tucks every open-at-rest sheet; a sheet that doesn't cover the page hides. Runtime bdLayers(): is-st-open/peek/tuck/hidden on .bd-ly-k, page on a sheet = --i on .bd-ly-track (snaps instantly when the sheet isn't open, so it only slides back), pushState, Escape/back, About-style toggle.
- Opening transitions (LAYER_TRANS, site.layers.trans; page.trans overrides — Space & card → Opens with, pages underneath only): slide, fold, unfold, squash, drop, push, rise, cut — sheetStateCSS writes every state per edge and per transition (desktop prefix is-e-, phone is-em- inside the one mobile block). page.transDur → --ly-pdur.
- Preview pane: with a sheet selected (S.sheetSel, S.spread !== false, not Preview) the canvas shows the SPREAD — spreadDoc(n, phone) in an iframe.bd-spread: the whole sheet laid flat at real px (exportCSS + layerBody per page in .bd-sp-slot > .bd-ly-pane[data-page], the strip page restyled as a pane), other sheets as dashed ghosts, the away ghost, the window frame (.bd-sp-win), a tap overlay per page (.bd-sp-tap → postMessage bdSpreadPage → goPage). fitSheet zooms down to 12% for it. The ruler offers Spread | Window (spread-view / window-view = S.preview). Canvas: a page on a sheet is drawn as the sheet shrunk to the page's margins on a grey desk (layerEditCSS; % = share of the drawn 1280×800 / 390×780 window via BOX_VIEW), with the peeking sheets above drawn at their edges (layerEditChrome renders their rest pages); the edge page is drawn at least 120 px / 40 px (phone) even when peek is 0. Before: the page on its sheet's paper, with the peeking sheets above drawn at their edges (layerEditChrome renders their rest pages); a rest page is edited at strip size (.bd-site.is-strip). Preview renders the real export in an iframe (kept in place; see Panels).
- Site → On every page: Page title at the top (site.header; a page switches itself off with page.header=false) and Click images to zoom (site.zoom; an image opts out with props.zoom=false). followV1 (once) clears the old blanket per-page / per-image overrides so the site switches work. With layers on and one menu, Site shows just that menu's links (no picker).
- Classic set: migrateSheets runs once when layers are on and site.sheets is missing. The old three-sheet output is pixel-identical (tests/states.py).

## Looks: master + override for every block type
Styles → Blocks sets the default look per block type (BLOCK_STYLE); a block's own Look fields override it ("Site" = follow the master). Now covers text, image, gallery, notes, list, link, video, rule, quote, posts, library, toggle, product, pager, post info, menu, page title. Images, galleries, library covers and post card images have a blend mode (mix-blend-mode) plus a "blend against colour" backdrop (a blend shows nothing on white otherwise), tone/opacity/corners.
- BS_WHEN hides fields that do nothing in the current state (tracing-paper fields only with Card look = Tracing paper, staples only with Zine, spine only with Book look, backdrop only with a blend, etc.).
- Every block with a master shows Look in its own panel; if Site/Page CSS has rules for that block (.bd-e-<id>, usually from Inspect) Look warns and offers "Remove the code overrides". The CSS fine-tuner (Inspect bar) sits folded under Look.
- Layers mode hides what a layered site doesn't use: + Header/Footer, floating menu button, page arrows at the end, Continue with other pages; the rail offers Sheet menu instead of Menu.
- Audit: /home-style test sets every BLOCK_STYLE field as master and as override and checks canvas + export change (see session notes); keep new fields wired in blockRules.
- THREE PANES (left → right): Layers (a Master row, then the Pages list; every page row and sheet title has a grip — drag a page to reorder it, move it onto another sheet or out to No group, drag a sheet to change the stack; pointer events, works on touch) · Settings (S.sheetSel → sheet panel, a page, a block, or Master) · Preview (the canvas). The column grid (rulerCols) is no longer on the canvas ruler: it is the page panel's "Columns & grid" fold. Master (S.masterSel, masterPanelHTML) holds Styles · Motion · Site (the old left tabs, via panelHTML); the settings pane is 340px, 420px for a sheet or Master (--e-rw). Code is a top-bar button that still opens the wide left pane (S.leftTab="code"). Code is no longer a bottom drawer: it opens as a wide left pane (has-wide-left). Views: Full CSS (default, read-only, exactly what Publish writes), Your CSS (site.css), Page CSS, This block (selected block's published HTML — editable for text/html — plus every published rule that styles it, via elRules), Page HTML, JS, Head, Files. Tapping a block with Code open switches to This block. With Code open, any tap on the canvas inspects the deepest element under the finger (S.codeNode, found by box because editing disables pointer events inside blocks): its HTML plus every published rule that matches it (nodeRules uses element.matches, ignoring :hover/::before).
- Blend "Lines only · drop the white" (value ink): the rule writes mix-blend-mode: multiply plus the marker --bd-ink-img: 1. Runtime bdInk() (in bd.js, also run on the edit canvas) bakes every marked image once: canvas → white becomes transparent, dark becomes the text colour → PNG data URL, then blend back to normal. Multiply alone failed in Safari because the sheets (transform/backdrop-filter) isolate the blend; the bake works everywhere. Images it cannot read (other domains) keep plain multiply.
- Panels: the two buttons at the top corners hide/show the left and right panels on wide screens (S.hideLeft/S.hideRight, saved in localStorage bd-hide-left / bd-hide-right; classes is-no-left / is-no-right on .bd-ed-app).
- Motion tab: paper-sheet motion (layers presets/ease/speeds/tilt/shadow/reveal), gestures (site.motion: gDur, gEase, tease, open → --bd-g-* tokens used by zine/trace/library transitions and the gesture delays in bdGalleries), and the master card look/hover/slide for Blog posts and book look/hover for Library. Those motion keys are skipped in Styles → Blocks (BS_GROUPS "Motion" group) but still overridable in a block's Look → Motion.
- Look fields are grouped (BS_GROUPS): posts Text / Card / Card image / Tracing paper / Zine / Motion; library Covers / Book / Motion; quote Text / Box; menu Links / Name.
- Tools (site.editor: layout, hidden, order, moved, custom — saved with the site): every top-bar button, rail button, left/right tab and panel section can be hidden, brought back, reordered and moved. The ⋯ at the end of the top bar, the rail and each tab strip opens the Tools sheet for that zone. Buttons move between top bar and rail; tabs between left and right (the right panel then gets tabs: Selected + moved panels); sections between any panels (ids from their headings: "<panel>:<slug>"). toolLayout() fills in anything new at its usual place.
- Add tool: code box; the code calls BD.tool({ id, name, kind: button|panel|section, icon (20×20 svg inner), zone (top/rail · left/right), panel (for sections), run(api) / render(api), actions: { name(api, el) } → data-act="tool-fn" data-tool data-fn }). api: site, page, block, state, set(path, v), change(fn), render(), say(msg), css(), uid, ui (field, row, sw, seg, select, input, numIn, colorIn, esc, icon). Errors show in the Tools sheet, never break the editor. Custom code runs with full editor access.
- Editor theme: monochrome warm greys, mono tabs, black for what's on.
- Panels: left = the base for everything (Pages list, Styles masters, Motion, Site incl. the sheet Stack order); right = what's specific to the selected page or block, including its sheet. Typing in a field redraws the canvas 160 ms after the keys pause; picks and switches redraw at once.
- Page → Space & card (pageBoxPanel; page.box: mt/mr/mb/ml margin, pt/pr/pb/pl padding, each with an M phone value that falls back to desktop; card (blank = part of the sheet's paper), cardA see-through %, blur, radius, shadow none/line/hard/soft, maxW, fit) plus page.sheetBg = behind the page. Values: number = px, % = of the window (top/bottom → vh, sides → vw). pageBoxCSS writes .bd-panel.bd-pg-<id> (every page panel carries bd-pg-<id>); pages underneath add the peeking-sheet insets; pages on sheets via .bd-ly-pane[data-page]. Old sheetPadT/X migrate into box padding on load.
- Preview with layers keeps its iframe: a look-only change restyles it in place (#bd-prev-css); a content change rebuilds after typing pauses (380 ms) and reopens the page you were on with the same scroll (parent.__bdPrevKeep). Lines-only drawings are baked once into blob URLs (window.__bdInkCache, keyed by src + ink colour), shared with the preview — assigning a blob src again is free, so re-renders don't re-decode 30 PNGs.
- Editor shades: panels sit on --e-bg, each section is a card (--e-surface), open folds and groups use --e-tint, tool rows alternate.

# Samt · CLAUDE.md

## What this is
Static site for samt.co on Cloudflare Workers (static assets, free plan). Pushing to `main` deploys.
Source of truth is `content/samt.json`; the Samt back office at /admin edits, previews and publishes it.
Samt has its OWN back office (since Oct 2026). It no longer uses the Site Grid editor shared with walidalwawi.com.

## The layer site (Walid's sketch)
Three translucent sheets, each blurring what's under it (backdrop-filter):
- **Menu sheet** (top, z 3): desktop = a column on the left (it's a full-width sheet parked off-screen with only its right edge showing); phone = a band on top. About is written on its hidden part: tapping About slides the whole sheet over everything (right on desktop, down on phone). Menu words ride its edge.
- **Index sheet** (middle, z 2): tracing paper, two screens tall — Journal cards on the top half, Library on the bottom half. Journal ↔ Library = it slides down/up. Opening a post slides it away (left on desktop, up on phone) leaving a sliver (`index.sliver` / `sliverM`). About from a post keeps it tucked (`is-tucked`).
- **Content layer** (bottom, z 1): every post and page is pre-rendered as an <article>; one is `.is-shown`. The featured post lies under the index, blurred. Scrolls on its own.
- Every URL (/, /library, /about, /<post>, /<page>) is the same document with a different starting state, so links and no-JS work. `site/assets/samt.js` moves the sheets and uses pushState.
- Type: exactly two sizes (Large: menu, mark, post title on phone · Small: everything else) plus a mono for information, always smaller than Small.

## Files
- `content/samt.json` — posts (blocks: text, image, quote, list, product, html), library items, about blocks, pages, menu, `look` (all settings; empty keys fall back to DEFAULTS in samt-render.js), custom `css`.
- `site/admin/samt-render.js` — DEFAULTS, fonts, easings; renders every page HTML and `site/assets/samt.css`. Used by the back office for the live preview and for Publish. Runs in Node too (`require`).
- `site/assets/samt.js` — runtime for the public site (not generated; edit by hand).
- `site/admin.html`, `site/admin/samt-admin.js`, `site/admin/samt-admin.css` — the back office.
- Generated by Publish (don't hand-edit): `site/*.html`, `site/assets/samt.css`, `content/manifest.json`.

## Back office
Top bar: Content · Layers · Type · Motion · Site, Desktop | Phone, undo/redo, View site, Publish (⌘S). Sub bar per tab, plus preview buttons (Journal, Library, Post, About) that drive the live preview by postMessage.
- Content: Journal (posts, card image, featured = lies under the index, hidden, blocks), Library (search, covers from Drive links or uploaded), About (blocks on the menu sheet), Pages (Supply etc., can be shown in the menu).
- Layers: Menu sheet, Index sheet + journal cards, Library, Post, Ground. On Phone, every paired number edits the phone value.
- Type: Sizes (Large / Small / Mono with limits), Fonts, Colour.
- Motion: Presets (Paper, Heavy drag, Stop-motion, Tracing, Quiet, Still), Sheets (feel/easing, speeds, tilt while moving, hard shadow while moving, settle one by one, how the post appears), Gestures (journal card: lift / nudge / tilt / tracing sheet; book: swing / lift / tilt). Play buttons replay moves in the preview.
- Site: General, Menu (rename, reorder, show), Custom CSS, GitHub.
- Draft autosaves to localStorage `samt-draft` until Publish. Images upload as git blobs right away and are added to `site/images/` in the publish commit.
- Publish = one commit: content/samt.json, content/manifest.json, every page .html, site/assets/samt.css (stamped "PUBLISHED <id>"), new images. Pages in the old manifest but not the new one are deleted. Then polls /assets/samt.css for the stamp.
- GitHub key: localStorage `bd-gh-key` (same name as before, so the existing key on samt.co keeps working).

## Delivery format — non-negotiable
- Complete file replacements only. Never partial diffs.
- Output as inline code blocks, never file downloads (Walid works on mobile)

## CSS conventions ("Brutalist Architecture")
- Zero indentation, flush left · one property per line · /* SECTION */ comments
- bd- namespace · is- / has- state classes
- Desktop-first; ALL mobile styles in ONE media block at the end (760px for the site, 900px for the back office)

## When unsure
Ask before assuming.

## Samt house style — "deadpan gesture" (fixed, Walid's choice)
- Interactions mimic one real-life gesture, stripped to a diagram: the library book cover swings open ~24° on tap (flat grey spine, hard shadow, no textures, no realism).
- One small physical gesture per element, never decoration: brutalist surfaces, the motion supplies the humour.
- Keep it flat: solid colours, hard shadows, simple transforms (rotate/translate). No gradients, no bounce, no 3D beyond a single hinge. Nothing fades — layers slide.
- Mobile first: hover only teases (desktop with real hover); a tap plays the full gesture and then opens.
- Colours: greys, beiges and whites, monochrome.
